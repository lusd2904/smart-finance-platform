# 任务中心使用说明

## 这个模块做什么

管理员启停、立即执行自动分析定时任务（热度、选股、因子、舆情、自动交易扫描等）。任务在后台跑，本页刷新看上次/下次时间与执行日志。各账户是否真实下单不在本页决定。

## 使用前

- 「任务中心 → 自动分析任务」默认仅管理员可见。业务账号改自动交易去「量化交易 → 策略配置」。
- 页顶须显示 **jobs 在线**。离线时不要点启用或立即执行，先让调度容器起来。
- 长任务入队后由对应消费组执行，不在登录接口进程里跑模型或采集。页面只提交、刷新、看日志。
- 新环境要先跑增量 SQL（`python3 scripts/sql_migrate.py apply`）。只起容器不迁移时，登录可能通，热度/选股等表会缺。

## 操作步骤

1. 打开侧栏「任务中心 → 自动分析任务」。确认「jobs 在线」和调度心跳时间。
2. 用「行情 / 量化 / 舆情 / 交易」筛选。开关即启停该 Job（需 `analysis:job:edit`）。
3. **立即执行**：点卡片上的「立即执行」（需 `analysis:job:run`）。请求很快返回，任务在后台跑；过一会儿点「刷新」或「执行日志」看结果。不要连点。
4. **智能选股**：找到「全市场智能选股」。卡片上的调度时间默认是北京 **15:50 / 16:50 / 05:50**（容器 cron 为 UTC）。本页负责启停和立即执行；改 cron 到「系统监控 → 定时任务」编辑该任务。不必为选股重启整栈。
5. 热度、收盘日 K、自选小时分析、因子日扫、次日清单、自动交易扫描、飞书推送都在本清单。自动交易扫描描述为扫美/港 Top50（叠加各账户美/港自选），A 股不扫；是否下单看该账户自动交易开关，与本页 Job 启停分开。
6. 窗口型任务（收盘 K、开盘送单、自动交易扫描）若这一轮入队失败，本轮会跳过、不会在调度里内联重跑。需要当次结果时在本页再点「立即执行」，或等下一周期。

## 注意

- 紧急停机（Halt）只拦新单，不拦撤单。停机开着时，自动交易扫描即使 Job 是启用也不会提交新委托。
- 自动交易默认纸面（账户开关关闭只扫描不下单）。打开后按该账户长桥凭据下到模拟或真实账户。
- A 股不参与自动交易扫描与下单。
- 策略档按登录账户绑定；未指定用户时不会把所有自选混在一起跑。
- 运维更新不要 `compose down`，不要重建 MySQL / Redis / Influx。滚动业务容器用 `--no-deps`。
- 涨跌颜色：涨红跌绿。
- 手机底栏是 **自选 / 行情 / 选股 / 持仓 / 我的**。手机没有任务中心，选股结果在底栏「选股」下拉刷新即可。
- 任务在后台跑，页面刷新看结果。不要把 Grok / 采集和登录接口当成同一个按钮。

## 常见问题

1. **页顶「jobs 离线」？** 调度没起来。不要在本页反复点立即执行。等在线后再启用任务。
2. **立即执行后列表没变？** 已交给后台。看该卡片「上次」状态和执行日志。`retrying` 不是失败，前端不应当失败停看。
3. **选股不是收盘后出的？** 看该卡片上的调度时间是否仍是北京 15:50 / 16:50 / 05:50。手动出单用「行情中心 → 智能选股」的「生成选股单」，同样后台跑、刷新看表。
4. **打开了自动交易扫描就会下单？** 不会单凭 Job。还要该账户已配长桥 Key 且策略配置里自动交易为开，并且未紧急停机。关开关仍可扫描台账。
5. **Redis/任务票丢了？** 若单独重建了 Redis 卷，会话和队列会空，库表和行情时序还在。用户需重新登录，本页再补跑需要的任务。不要 `compose down -v`。

# AI 管理使用说明

## 这个模块做什么

配置模型、AI 对话、单标的研判，以及需求沟通群。选股默认用行情中心范围的 Grok 4.6。对话与总结入 `llm` 队列，不堵登录接口。飞书策略摘要在交易中心单独订阅。

## 使用前

- 须有「AI 管理」菜单。改模型要有 `ai:model:add/edit`。
- 先在「模型管理」填真实 Base URL 与 API Key。占位不要写成临时隧道主机，用 `https://your-openai-compatible-endpoint/v1` 这类 OpenAI 兼容地址。
- 智能选股 / 自选分析：适用范围选 **行情中心 (market)**，默认 Grok 4.6（OpenRouter `x-ai/grok-4.6`，直连 xAI `grok-4.6`）。未配行情模型时回退全局 / 助手。
- 舆情分析优先 `sentiment`。AI 对话用 `chat` 或全局。同一编码不要重复启用。
- 需求沟通「发送 / 总结」立即返回 `jobId`，由后台消费组调模型。离开页签会停轮询。

## 操作步骤

1. **模型管理**：侧栏「AI 管理 → 模型管理」。新增时填模型编码、提供商、适用范围、API Key、Base URL。智能选股必须有一条启用的「行情中心 (market)」。下次选股 / 研判会用新配置。
2. **AI 对话**：侧栏「AI 管理 → AI 对话」。左侧会话，顶栏选模型，输入发送。这是助手对话，不是选股批跑。
3. **单标的研判**：侧栏「行情中心 → AI研判」。选标的与市场，点「开始研判」或「One-Shot 全景」；「最新结论」拉已落库结果。批量扫描同一页另一个页签。HTTP 入 `llm` 队列后返回 ticket，页面刷新或等列表更新即可。行情交易台底部也有该标的已有结论，没有则来本页生成。
4. **需求沟通**：侧栏「AI 管理 → 需求沟通」。说明要做的需求，点发送；确认后点「总结并写入清单」，或在对话里说「确定需求，写入清单」。确定者写入「AI 需求清单」，开发测完在清单里改状态。机器人与唯一确定者在「AI 管理 → AI机器人」配；未配则群里默认 Grok。admin / niangao 不在群成员展示里。
5. **飞书**：侧栏「交易中心 → 飞书推送」。填个人/群 Webhook 与本地推送时间。两边都开才双发。非交易日、空清单、停牌日默认不推。推的是次日策略摘要（含免责声明），不是荐股，也不是需求沟通记录。
6. **手机**：「我的 → AI 研判 / 需求沟通」。需求沟通为对话气泡，轮询 `jobId`。

## 注意

- 紧急停机（Halt）只拦新单，不拦撤单。
- 自动交易默认纸面；A 股不参与自动交易扫描。策略档按登录账户绑定。
- 运维更新不要 `compose down`，不要重建 MySQL / Redis / Influx。
- 涨跌颜色：涨红跌绿。
- 手机底栏是 **自选 / 行情 / 选股 / 持仓 / 我的**。
- 研判 / 发送 / 总结在后台跑，页面刷新看结果。

## 常见问题

1. **选股结论不是 Grok 4.6？** 打开「模型管理」，确认有启用行且适用范围是「行情中心 (market)」，编码无误。否则会落到全局或助手。
2. **需求沟通点发送后像没反应？** 已入队。等气泡出现；有 `jobId` 时才轮询。离开页签会停 2.5s 轮询，回到本页再看。
3. **研判只回了一张票？** 正常。刷新「AI研判」或看任务结果，不要当成失败。`retrying` 是重试中。
4. **飞书没消息？** 先在「飞书推送」保存并点测试。非交易日/空清单不推。需求沟通内容不会发到飞书。
5. **Base URL 填错了？** 保存成你实际可用的 OpenAI 兼容地址。不要把临时隧道写进库。舆情「AI配置」页改不了密钥，只显示当前解析到的模型。

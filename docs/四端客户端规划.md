# 四端客户端统一规划（macOS / Windows / iOS / Android）

> 2026-08-24 立项。本文档是四端客户端的唯一规划基线，后续里程碑变更在此文档上迭代。

## 目标

用 **Flutter 单工程**交付四个原生客户端（iOS、Android、macOS、Windows），功能与 Web 管理台**全量对齐**（行情、舆情、量化、交易、AI 研判），四端同步首发。替代现有 `desktop/` Electron 壳；`ruoyi-fastapi-app/`（uni-app）的 App 侧职责由本工程接管。

## 已确认决策（2026-08-24 Q&A）

| 决策点 | 结论 | 备注 |
|---|---|---|
| 技术路线 | Flutter 四端一体，单工程出四包 | 官方正式支持四端的唯一方案 |
| 功能范围 | 四端全量对齐（含量化研究 + 长桥交易） | 手机端复杂交易界面需单独交互设计 |
| 桌面端 | 推倒 Electron 重做 | `desktop/` 过渡期继续服务，Flutter 桌面对齐后下线 |
| 交付节奏 | 四端同步首发 | 每个里程碑内四平台同跑同验 |
| 分发基线 | Android APK 直装 + iOS TestFlight + macOS 公证 dmg + Windows 无签名 exe | iOS 只走 TF 不上架商店；Windows 接受 SmartScreen 警告不买证书；商店上架列为后续合规任务线 |

## 现状调研（规划依据）

- **后端**：FastAPI 统一 JWT 鉴权；网关 = 前端 nginx 反代 `/docker-api`（`docker-compose.sentiment.yml`，端口 12580）；四端可零改动复用同一套接口。
- **实时通道**：后端**无 WebSocket/SSE**，行情台报价读 Redis / SWR + 轮询；交易实时在独立进程。客户端第一期同样走轮询即可。
- **桌面现状**：`desktop/`（Electron 34）：首启「网关配置 → 探测通过 → 登录页」交互成熟，含沙箱桥接白名单、网关地址校验提示。这套交互在 Flutter 中复刻。electron-builder 已配 mac dmg/zip + win nsis，但无签名公证、无自动更新。
- **移动现状**：`ruoyi-fastapi-app/`（uni-app 3.0）只有登录/注册/工作台/我的骨架页，无金融业务页面；默认构建目标是微信小程序。`todos.md` 第 14 条「移动端暂不升级」的约定被本规划取代（App 侧）；其 H5 有活跃用户，**双轨保留**（不归档），Flutter 接管原生 App 职责。
- **接口域清单**（客户端按此对齐）：
  - `system`：登录/注册/验证码/用户信息/菜单权限
  - `market`：市场热度、Top50 快照、全部股票分页（`/market/instrument/universe`）、自选（`market_watchlist` 按 user_id）、日/周/月 K线、分时（Influx `minute_kline`）、财经资讯、AI 研判结果
  - `sentiment`：舆情大盘、资讯列表、分析历史
  - `quant`：因子、IC/IR/分层收益、策略信号、扫描台账、8 族权重、长桥配置（按用户行，保存掩码）
  - `trade`：长桥账户/持仓/委托、盘口深度、纸面自动交易、风控规则与事件、通知中心
- **CI**：`.github/workflows/ci.yml` 已有 pip-audit 门禁与双镜像构建冒烟；Flutter 构建流水线为新增矩阵。

### 关键技术选型

| 关注点 | 选择 | 理由/备选 |
|---|---|---|
| 状态管理 | Riverpod | 社区主流、可测；备选 bloc |
| 网络 | Dio + JWT 拦截器 | 对齐后端 `code/msg/data` 响应包与 token 失效语义 |
| K线图表 | CustomPainter 自绘蜡烛图/分时 | 金融 K线无完美现成包；起步可用 `fl_chart` 占位再替换 |
| 数据表格 | Syncfusion DataGrid | 注意社区许可边界（公司收入 <$100 万免费）；备选 `material` DataTable2 |
| 自适应布局 | 单代码库双壳：手机底部导航单栏；桌面侧栏 + 多栏 | 自选三栏等页面按断点切换 |
| 平台差异 | 条件导入 + `Platform` 判断 | 推送、窗口行为、更新检查各自实现 |

### 后端配合改造（新增任务线）

1. **版本检查接口** `GET /app/version?platform=&version=`：返回最新版本、下载地址、强制升级标志（APK 直装渠道必需）。
2. **推送服务**（module_push）：APNs + FCM；事件源对接风控事件、成交回报、涨跌提醒（jobs 队列投递）。第一期降级方案：应用内通知轮询，推送作为 M5 增强。
3. **（可选优化）SSE/WebSocket 行情通道**：替代轮询；非首发阻塞项。
4. **中间件兼容核查**：确认 IP 归属地、审计日志、限流对非浏览器 UA / 无 Referer 请求的兼容。

| 类别 | 规范 |
|---|---|
| 色彩 | 品牌蓝 `#409EFF` 对齐 Web 端；涨红 `#E5484D` / 跌绿 `#30A46C` / 平灰 / 警示琥珀，唯一取用处 `AppColors`；页面禁止散落裸色值 |
| 几何 | 卡片圆角 14、控件圆角 10、页留白 20、内容最大宽 1280、断点 ≥900 桌面壳（≥1200 侧栏展开）——见 `AppDimens` |
| 数字 | 报价/金额一律 tabular figures（`AppNum.style`），详情页大价格用 `quoteDisplay` |
| 组件 | 页头 `PageHeader`、分区卡 `SectionCard`、统计格 `StatGrid`（<600 两列/<900 三列/其余四列）、品牌标 `BrandMark`、状态点 `StatusDot`、认证页骨架 `AuthScaffold` |
| 导航 | 手机底部 NavigationBar；桌面品牌侧栏（logo 字标 + 药丸导航 + 底部网关状态灯）；tab 用 IndexedStack 保活 |
| 入口链路 | 网关配置 → 登录/注册共用左右分栏品牌面板（窄屏收起为顶部字标） |

**后续里程碑套用规则**：M2 资讯/AI/通知、M3 量化图表、M4 交易台的新页面一律复用上述组件与令牌；新增组件先进 gallery 预览页登记再上业务页。

## 测试策略

- **integration_test**：每里程碑覆盖关键路径——登录→热度→加自选→开K线（M1）；研判查看（M2）；因子图表加载（M3）；纸面下单闭环（M4）；版本检查提示（M5）。
